# Learn
Read release results, issues, user feedback, metrics, and decisions. Separate observation from interpretation. Capture product/technical/operational learnings, escaped defects, invalidated assumptions, cost/performance surprises, and new constraints. Append; do not rewrite history. Recommend second-brain updates when company-wide. If learning implies a locked upstream change, present it and ask one question; do not mutate automatically. Stop.
