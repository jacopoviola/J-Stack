# UX Psychology Stress Test (Growth.Design method)

Think like the Growth.Design authors: walk a product the way a real user would, screen by screen, and at every step ask what the user notices, believes, does and remembers. Name the psychological principle at play, show the evidence on the screen, and cite a real product that got the same moment right or wrong. The value is in the specificity: "this paywall triggers reactance because the decline button is labelled 'No thanks, I don't want to improve' (see Strava, case 3)" beats "consider user psychology".

Two modes, same engine:

- **Design mode** — the user is building something ("help me design the onboarding for…"). Output: the principles to design *with*, what each one changes on the screen, cases to steal from.
- **Stress-test mode** — the user has something to evaluate ("tear down my checkout", "why is nobody converting"). Output: a psych walk-through of the flow, the moments where psychological energy drops, ranked fixes, and any ethical red flags.

If it isn't clear which mode applies, infer from whether the thing exists yet; ask only if the answer changes the output.

## Step 0 — Intake: infer first, ask only for gaps

Principles are selected by **journey moment and user state**, not by industry. Extract these from whatever the user gave (description, screenshots, URL, doc). Fill what can be inferred, state the assumptions you made, then ask only for what is still missing.

| # | Dimension | Extract | Which principle families it switches on |
|---|---|---|---|
| 1 | Job & frequency | JTBD + daily habit / episodic / one-shot | Habit → Time + Memory families (triggers, investment loops, variable reward, Zeigarnik, spacing, exit points). One-shot → Information + Meaning only. |
| 2 | Money model | Trial subscription / freemium upgrade / transactional / ads-engagement / marketplace | Locates the tension moments (trial→paid, upgrade, checkout, cancel) where dark-pattern risk lives (loss aversion, default bias, sunk cost, reactance, cashless). |
| 3 | Stakes & reversibility | Money, data, privacy, health, safety? Undoable? | High → trust family (labor illusion, feedback/feedforward, framing, negativity bias). Low → speed family (System 1, defaults, Fitts, Hick's, spark). |
| 4 | Novelty vs familiarity | Existing mental model for the category? | Familiar → mental model, familiarity bias, recognition over recall. Novel → early aha moment, curse of knowledge, show-don't-tell, storytelling. |
| 5 | Emotional state at entry | Anxious / bored-leisure / goal-driven under time pressure | Affect heuristic + empathy gap set how much friction and persuasion is tolerable. |
| 6 | Decision architecture | Number, order, pricing and framing of options | Hick's, decoy, centre-stage, anchoring, unit bias, cognitive load, decision fatigue. |
| 7 | Business/user divergence | Where does the company win if the user loses? | Tells you where to hunt for manipulation and which cases to read as warnings. |
| S | Flow(s) in scope | Which screens/flows; or "whole product" | Selects the cluster(s) in the flow map. Whole product → walk acquisition → onboarding → activation → monetization → retention → offboarding. |

Gap rule: dimensions 1, 2 and S change everything — ask if they can't be inferred. For 3–7, make the most plausible assumption, say so explicitly, and only ask if it would flip a recommendation. Never turn the intake into a questionnaire for someone who already wrote three paragraphs.

## Step 1–6 — Selection procedure

1. **Tag** the product on the dimensions above.
2. **Cluster**: pull the flow(s) in scope from the flow map below.
3. **Walk the flow step by step.** At each step run the four-phase loop (this is Growth.Design's "psych" cycle — every step of a journey either adds or drains psychological energy) and pull candidates from the principle list:
   - *Information* — does the user even notice what matters? (hierarchy, contrast, signifiers, cognitive load, banner blindness, progressive disclosure)
   - *Meaning* — do they understand and believe it? (mental model, framing, social proof, feedforward, curse of knowledge, aha moment)
   - *Time* — will they act now or shortcut/abandon? (defaults, loss aversion, reactance, decision fatigue, hyperbolic discounting, temptation bundling)
   - *Memory* — will they remember, return, and recall it positively? (peak-end, Zeigarnik, triggers, delighters, spacing, exit points)
4. **Re-rank** with the modifiers (stakes, frequency, novelty, emotion, divergence). Keep the 3–6 principles that actually move the outcome at that step; drop the rest. A list of 20 principles is a sign the walk wasn't done.
5. **Attach relevant cases** (1–3 per principle) from the flow map and the `[cases …]` tags in the principle list. Decide the framing per situation — the same case can *demonstrate* (done well), *debunk* (backfired / manipulative) or *make us think* (a tradeoff). Say which and why. Read the full teardown when the detail matters (see "Going deeper").
6. **Run the ethical line** on every persuasion principle (scarcity, social proof, defaults, loss aversion, labor illusion, framing, variable reward): is it true, relevant to the user, in the user's interest, and would the user feel tricked seeing behind the curtain? Any "no" turns the principle from a recommendation into a risk. Growth.Design's recurring conclusion: the same mechanism is good UX when it reflects reality and helps the user, a dark pattern when it fabricates pressure or hides consequences.

## Output formats

Write in the user's language (this user usually writes in Italian; match them). Prose over bullet dumps; every principle named must come with the on-screen evidence and a case. Keep principle names in English (they're the shared vocabulary) and explain them the first time.

**Stress-test report**

```
# UX Psych Stress Test — <product / flow>
## What I assumed (intake)            ← the 7 dimensions + scope, marking inferred vs stated
## Psych walk-through                 ← one short block per step: what the user notices / believes / does / remembers, psych level ↑ or ↓, principle(s) at play, evidence on screen
## Where the energy drops             ← the 3–5 moments that most likely cause drop-off, ranked by impact
## Fixes                              ← per moment: the change, the principle it leans on, the case that shows it working (or failing)
## Ethical red flags                  ← anything that fails the ethical line, and the honest alternative
## Cases worth reading                ← 3–5 case studies with why, framed demonstrate / debunk / think
```

**Design brief (design mode)**

```
# UX Psych Design Brief — <product / flow>
## What I assumed (intake)
## Principles to design with          ← 3–6 per flow, each: what it is, what it changes on this screen, the risk if overdone
## Screen-by-screen guidance          ← in journey order, four-phase check per screen
## Steal from                         ← cases to copy, with the specific pattern to copy
## Don't do                           ← cases that debunk the obvious move
```

Skip sections that would be empty rather than padding them. If the user asked a narrow question ("which principle explains X?"), answer it directly in a paragraph with the case — don't force the template.

## Reference A — The 106 principles (four phases, with the cases that name them)

Growth.Design's phases: **Information** (users filter out a lot of what they receive, even when it matters) → **Meaning** (users make stories and assumptions to fill gaps) → **Time** (users are busy, take shortcuts, jump to conclusions) → **Memory** (users remember what their brain prefers, not what mattered).

4 Cognitive Load: Total amount of mental effort that is required to complete a task [cases 4, 13, 23, 49]; 5 Anchoring Bias: Users rely heavily on the first piece of information they see; 6 Nudge: Subtle hints can affect users' decisions [cases 10, 16, 39, 42]; 7 Progressive Disclosure: Users are less overwhelmed if they're exposed to complex features later [cases 23, 24, 33, 38, 46, 49]; 8 Fitts's Law: Large and close elements are easier to interact with [cases 17, 31, 32]; 9 Attentional Bias: Users' thoughts filter what they pay attention to [cases 30]; 10 Empathy Gap: People underestimate how much emotions influence user behaviors; 11 Visual Anchors: Elements used to guide users' eyes [cases 21]; 12 Von Restorff Effect: People notice items that stand out more [cases 30]; 13 Visual Hierarchy: The order in which people perceive what they see; 14 Selective Attention: People filter out things from their environment when in focus; 15 Survivorship Bias: People neglect things that don't make it past a selection process; 16 Banner Blindness: Users tune out the stuff they get repeatedly exposed to [cases 10, 23, 24, 37, 40]; 17 Juxtaposition: Elements that are close and similar are perceived as a single unit;
